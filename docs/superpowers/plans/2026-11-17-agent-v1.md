# LifeFlow Agent V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver persisted SOP execution and user-approved, tool-driven replanning.

**Architecture:** Keep the existing frontend and Worker. Add a deterministic
execution module, revisioned D1 persistence, and a bounded tool-calling loop.
The model may propose changes but cannot approve its own changes.

**Tech Stack:** React 19, Zustand, Cloudflare Workers, D1, OpenAI-compatible API.

**Spec:** `docs/superpowers/specs/2026-11-17-agent-v1-design.md`

## Global Constraints

- Retain the existing stack and cooking scope for V1.
- Do not overwrite completed, skipped, or running steps through replanning.
- D1 owns execution state; frontend state is a cache.
- Maximum four model calls, eight tool invocations, and 60 seconds per turn.
- No remote migrations, push, or deployment without a separate request.
- Commit each verified implementation task separately, as requested by the user.
- Repository currently has no automated test suite. Use temporary executable
  validation scripts under the task workspace and local integration checks;
  do not add a permanent test framework without approval.

## Review Focus

- Refresh or pause/resume must retain actual progress and timer deadlines (Task 2/4).
- Duplicate confirmation must apply exactly once, including concurrent requests (Task 2).
- Stale proposals must not overwrite newer execution or timer state (Task 2).
- Invalid model output, injected roles, and repeated tools must fail safely (Task 1/3).
- Missing credentials and network errors must never look like successful plans (Task 1/4).

**Interfaces**

- `POST /api/executions` with `{sopId, requestId}` starts/restores an active session.

- Repository methods: `getExecution(userId, id)`,

- `validatePlanChange(execution, candidate)` rejects changes to nonpending work.
